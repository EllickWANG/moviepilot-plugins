# IYUU自动辅种增强

插件 ID：`IYUUAutoSeedPlus`

## 用途

本插件复刻官方 `IYUUAutoSeed` 2.15，并额外增加批量查询、IYUU 请求超时、下载器请求超时和站点域名匹配配置，用于解决 IYUU 查询接口在大量 hash 场景下容易 20 秒超时、qBittorrent Web API 偶发卡住，以及 IYUU 返回域名与 MoviePilot 统一站点配置不一致的问题。增强版也会避免同一实例重复执行辅种任务，并在插件重载时通知旧任务尽快停止，避免旧配置继续跑。

官方插件默认每批提交 200 个 hash，并使用 MoviePilot 默认请求超时 20 秒。线上出现过以下日志：

```text
下载器 fn-main 保种 开始查询辅种，数量：200 ...
请求失败: HTTPSConnectionPool(host='2025.iyuu.cn', port=443): Read timed out. (read timeout=20)
当前种子列表没有可辅种的站点：请求IYUU失败，未获取到返回信息
```

增强版将这些参数改为可配置：

- `IYUU请求超时(秒)`：默认 `60`，范围 `5-300`。
- `下载器请求超时(秒)`：默认 `15`，范围 `3-300`，用于 qBittorrent 独立查询、添加种子和设置分类请求；其他控制请求沿用宿主配置。
- `每批查询Hash数`：默认 `50`，范围 `1-200`。

同时增强版会统一处理站点下载链接拼接，避免站点地址末尾没有 `/` 时生成 `example.comdownload.php` 这类错误；需要访问站点详情页提取下载链接时，也会使用插件中的请求超时配置。

## 与官方插件的关系

- 官方插件 ID：`IYUUAutoSeed`
- 增强版插件 ID：`IYUUAutoSeedPlus`

增强版是独立插件，不覆盖官方插件。建议二选一启用，不要同时启用官方版和增强版，否则可能重复扫描同一个下载器并重复辅种。

## 安装

在 MoviePilot 插件市场添加私人仓库：

```text
https://github.com/EllickWANG/moviepilot-plugins
```

搜索并安装：

```text
IYUU自动辅种增强
```

安装后建议停用官方 `IYUU自动辅种`，只保留增强版。

| 清除缓存后运行 | 关闭 | 清理成功、失败缓存后再执行。 |

| 执行周期 | 空 | 标准 5 段 cron，例如 `0 1 * * *`。 |

| 主辅分离 | 空 | 可指定单独辅种下载器。 |

| 辅种站点 | 空 | 只对选定站点辅种。 |
| 不辅种标签 | 空 | 命中标签的原种跳过，多个用英文逗号分隔。 |

| 自动开始(跳过校验有效) | 关闭 | 跳过校验时自动开始任务。 |
| 固定辅种分类 | 关闭 | 开启后辅种分类固定使用“辅种后增加分类”，保存路径仍使用原种真实保存路径。 |

## 推荐配置

当前线上 `fn-main 保种` 已完成种子数量在几百级别时，推荐先用：

```text
IYUU请求超时(秒)：60
下载器请求超时(秒)：15
每批查询Hash数：20
执行周期：*/30 * * * *
```

如果仍然超时：

```text
每批查询Hash数：20
IYUU请求超时(秒)：90
```

如果 qBittorrent 经常 `ReadTimeout` 或 `Forbidden`，优先把 MoviePilot 下载器地址改成 qB 内网地址；仍需要走反代时，可以用“下载器请求超时(秒)”控制等待时间。想减少单轮任务占用时间可设为 `8-10`，想容忍慢链路可设为 `30-60`。

如果 IYUU 返回很快，可以逐步调大每批数量，例如 `80` 或 `100`。

如果日志里出现 `没有维护种子对应的站点：www.example.com`，但 MoviePilot 站点管理中实际已经有该站点，可以在“站点域名别名”中增加：

```text
www.example.com=example.com
```

也支持把 IYUU 返回的子域名映射到站点管理中的主域名，例如：

```text
na.example.com=example.com
```

不要使用：

```text
* 1 * * *
```

这代表每天 `1:00-1:59` 每分钟运行一次，会在一小时内跑 60 次。每天 1 点跑一次应写：

```text
0 1 * * *
```

## 执行逻辑

1. 扫描配置中的下载器。
2. 每轮任务开始前重新读取插件配置。
3. 读取已完成种子。
4. 按标签、路径、体积过滤。
5. 按“每批查询Hash数”切分 hash。
6. 调用 IYUU 查询可辅种站点。
7. 按站点域名、去 `www` 域名、别名配置和子域名兜底匹配 MoviePilot 站点配置。
8. 对可辅种结果下载种子并添加到下载器。
9. 根据配置设置标签、固定辅种分类、跳过校验、自动开始；保存路径始终使用原种真实保存路径。
10. 保存成功、失败缓存。

批次之间是相互独立的。比如 `每批查询Hash数=20`，本次需要查询 `100` 个 hash，会拆成 5 批。如果第 1 批因为 IYUU 超时失败，只会放弃第 1 批本次结果，不会把这些 hash 写入失败缓存；后面的第 2 到第 5 批会继续执行。下一次任务仍会重新尝试第 1 批。只有插件被停用、重载或服务停止时，才会在当前请求返回后停止后续批次。

## 常见问题

### 插件打开后运行态仍然是关闭

增强版保留官方判断逻辑，必须同时满足：

- 已启用插件
- 已填写执行周期
- 已填写 IYUU Token
- 已选择下载器

缺任意一项，运行态都会是关闭。

### 仍然提示 IYUU 超时

先把“每批查询Hash数”降到 `20`，并把“IYUU请求超时(秒)”提高到 `90`。如果仍然失败，多半是 IYUU 当前服务端繁忙或网络链路抖动。

### 提示站点哈希值 require

这是 IYUU 的站点哈希 `sid_sha1` 没有初始化成功，通常发生在 `/reseed/sites/index` 或 `/reseed/sites/reportExisting` 超时后。增强版会在拿不到 `sid_sha1` 时跳过本批，不再继续发送无效查询；下一批或下一轮任务会重新尝试初始化。

### qBittorrent 经常 ReadTimeout 或 Forbidden

`IYUU请求超时(秒)` 不控制 qB。辅种查询、添加和分类请求由“下载器请求超时(秒)”控制，其他控制请求沿用宿主配置。查询目标 hash 失败时会跳过本次添加，避免无法确认是否已存在时重复添加。

从 2.15.14 起，IYUU 的种子查询使用独立且串行的 qB 客户端，避免与宿主后台任务并发复用会话。连接异常时销毁旧会话，再用新会话重试一次；认证失败及非法响应不自动重试。保留宿主已有的证书校验、代理和认证设置，不改写宿主的全局超时。

普通添加下载成功，不能据此判断种子查询始终正常。出现 TLS EOF 时日志会明确标记“连接提前断开”，不会将依赖库通用的自签证书提示当作证书诊断结论。若独立会话重试后仍失败，需要结合当时的宿主日志和下载器链路继续排查。

### 校验队列一直检查、但没有开始辅种

- 每批最多查询 50 个 hash；只有查询成功的批次才会清理已经不存在的任务，失败批次保留。
- 只有文件完整且暂停的 qB 任务会被启动；缺失文件、读写错误、未完整匹配的暂停任务会打印名称、hash、状态和检查建议，不会强制启动或补下数据。
- 已经开始做种的任务会移出校验队列。启动请求接受后也会保留队列，等后续查询确认做种状态；启动请求失败或抛出异常时下次继续处理。
- 日志区分“启动请求已接受”和实际做种状态；每次检查输出剩余任务及失败数量。相同待处理状态每半小时提示一次，状态改变时立即提示。

可以使用已登录的管理员凭据调用只读诊断：

```text
GET /api/v1/plugin/IYUUAutoSeedPlus/diagnose/downloader?downloader=<下载器名称>
```

仅允许诊断插件配置中选择的 qB 下载器。接口分别用宿主会话和 IYUU 独立会话读取一条种子记录，返回成功状态、耗时、尝试次数和待处理数量；不返回种子内容或凭据，不添加、删除、校验或启动任务。

2.15.15 增加可选的 `network=true` 参数，返回下载器域名解析耗时、IPv4/IPv6 地址及各一条 TCP/TLS 直连探测结果（每阶段最多 3 秒）。TLS 探测始终校验证书，只报告代理是否启用，不返回代理地址或凭据；使用代理时，直连探测与实际请求链路可能不同。诊断同时报告 Python、OpenSSL 和请求库版本。

2.15.16 增加“下载器查询直连”动态开关。MoviePilot 的进程环境代理可能影响 qB 请求；当直连 TCP/TLS 很快、继承代理的查询却超时或 TLS EOF 时，可以先使用 `direct=true` 临时诊断，与 `direct=false` 对比。这两个参数不保存配置；确认直连有效后再打开表单开关。直连仅作用于 IYUU 自己的查询客户端，不改环境变量、宿主客户端或证书设置。

2.15.17 将旧版 qB 添加种子后按临时标签查找 hash 的操作也统一到独立查询会话，避免添加接口返回 `Ok.` 后再次经过宿主代理。标签必须唯一匹配；可取消等待，不会因查询失败或标签歧义猜测任务 hash。

2.15.18 修复设置分类时的实例超时参数调用，并在扫描前初始化 IYUU 站点表和 `sid_sha1`。日志保留失败接口、HTTP 状态和业务错误；网络、HTTP429/5xx 等可重试错误最多重试三次，认证或响应格式问题立即终止本轮，不会继续跳过大量批次并误报扫描完成。初始化诊断可调用 `GET /api/v1/plugin/IYUUAutoSeedPlus/diagnose/iyuu`，只读取站点元数据，不添加任务。

校验队列会保存到插件数据，重载后恢复。维护时可以通过 `POST /api/v1/plugin/IYUUAutoSeedPlus/recheck/restore` 提交 `{ "下载器名称": ["hash"] }`，只接纳已配置 qB 下载器中、带当前辅种标签的现有任务；接口本身不启动或添加种子。`GET /api/v1/plugin/IYUUAutoSeedPlus/status` 返回运行状态与各下载器待处理数量。

2.15.19 将启动、重新校验、临时标签清理和分类设置统一到独立会话，修复查询成功但启动仍经过宿主环境代理的问题。连接异常时仅对这四种幂等控制重建连接重试一次；添加种子仍使用宿主添加接口，并逐次传入直连参数，不因连接异常自动重复添加。直连开关沿用原配置键，表单名称更新为“下载器请求直连”。

### 提示没有可辅种站点

需要区分两种情况：

- `IYUU查询超时或网络异常`：这是接口超时，不代表真的没有可辅种。
- `当前种子列表没有可辅种的站点` 且返回 IYUU 状态码：这是 IYUU 正常响应后的结果。

### 提示没有维护种子对应的站点

这通常不是 IYUU 没有数据，而是 IYUU 返回的站点域名和 MoviePilot 站点管理中维护的域名对不上。增强版会自动尝试：

- 原始域名匹配。
- 去掉 `www.` 后匹配。
- 站点域名别名匹配。
- 子域名匹配主域名。

仍然匹配不到时，把日志中的域名按 `IYUU域名=MoviePilot站点域名` 写入“站点域名别名”。

### 是否会影响官方插件

不会。增强版使用独立插件 ID 和独立配置 key。建议停用官方版，避免重复扫描和重复添加。
