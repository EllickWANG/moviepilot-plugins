# 刷流

`FlowBrush` 是基于线上 `BrushFlow` 4.3.5 复刻的私人维护版，插件展示名缩短为“刷流”，配置前缀、服务 ID 与原插件隔离，避免与原 `BrushFlow` 同时存在时互相覆盖。

## 来源

## 配额与下载需求（4.4.0）

新增“单站同时下载上限”，按下载器实时返回的刷流下载任务统计，包含等待任务，跨调度轮次累计。与“每轮新增上限”同时生效；已有超额任务继续运行，只停止该站新增，并继续检查其他站点。任务归属优先使用刷流记录，缺失时精确匹配 `站点/站名` 标签；归属未知的任务保守占用每站一个名额，读取失败暂停本轮新增。全局下载数、带宽和保种体积限制仍然生效。

新增“最少下载人数”和“优先有下载需求的种子”。前者跳过下载人数不足或未知的种子；后者按下载人数与做种人数之比排序，同分时按下载人数、发布时间排序。可结合做种人数下限、发布时间、体积和免费筛选使用。启用发布时间限制后，缺失或无法解析发布时间的种子不再被当作刚发布。

上述选项支持单站覆盖，默认关闭以兼容旧配置。它们只影响新增，不暂停、删除或取消已有任务，也不改变 H&R 与保种清理条件。站点人数是站点提供的快照，不能保证实际传输速度；被移出新增范围的站点，其历史刷流任务仍按原有分站规则维护。

## qB 做种计时修复（4.3.10）

删种使用 qB 返回的 `seeding_time` 累计计时，不再用当前时间减去下载完成时间，避免把暂停、离线也计入保种时间。
计时缺失或异常、未完成全部文件、只下载选中文件时，做种计时按零处理，不回退到墙钟时间。

H&R 与普通删种阈值仍为独立配置，多个删种条件仍为“或”关系。按站规保种时，应同时设置普通及 H&R 做种时长，清空分享率、上传量、低速、闲置、下载超时阈值，并关闭动态删种、促销到期删种及同数据联删，防止其它条件绕过时长。
未核实站规的站点应清空全部删种条件。qB 本地计时不等于站点 Tracker 的有效做种记录；站点异常、认领种子等额外义务不能仅靠计时判断，需保留任务并核对站点记录。

## qB 下载器默认直连（4.3.9）

刷流连接 qBittorrent 时默认使用插件独立客户端，忽略环境及宿主客户端的 HTTP/HTTPS/ALL 代理。
查询、添加、检查、标签、重新汇报等下载器操作均沿用原有封装，但使用独立的直连会话。
重建会话后仍保持直连；初始化失败不会退回宿主的代理连接。
原账号/API Key 和证书校验配置保持不变，不修改系统环境、其他插件的共享连接或 qB 设置。
站点获取种子仍按站点的代理开关执行，直连改动仅针对 qB 下载器。

qB 带宽阈值现在基于所选刷流下载器的实际流量，不再通过核心汇总其他下载器的流量。
只读诊断增加 `connection_mode=plugin_direct` 和 `authenticated_read`，后者使用独立会话
登录并读取少量种子和传输统计，可验证认证后的访问是否恢复；不添加或更改种子。

## 从 Web 排查下载器连接（4.3.8）

在刷流设置中勾选“仅诊断下载器一次”并保存，然后在插件日志中搜索 `[刷流诊断]`。
该开关自动复位；诊断不会添加、暂停或删除种子，也不会重连或更改宿主共享的 qB 会话。
原有定时任务仍按配置运行；“立即运行一次”是刷流/检查任务，与只读诊断不同。
每次只允许一个诊断，至少间隔 60 秒。

结果包含运行时/客户端版本、DNS 地址、IPv4/IPv6 首个地址的直连 TCP/TLS 结果及耗时、
TLS 协议和证书有效期，以及新建 HTTP 会话是否选中了代理。
基础 TCP/TLS、HTTP 网络诊断始终校验证书；其新会话不发送 qB 账号、Cookie、授权头或客户端证书，不跟随重定向。
4.3.9 的 `authenticated_read` 另行使用已配置的认证和证书设置进行只读查询。
HTTP 401/403 表示服务可达但未认证；不能据此断言账号有效或种子添加成功。
直连失败而代理路径成功时应检查网络路由；新会话成功而刷流仍失败时，应进一步检查宿主会话和认证状态。
DNS 最多等待 3 秒，直连的连接及握手各最多 3 秒；HTTP 连接/读取超时各为 3 秒（系统解析和代理实现可能另有耗时）。

`[刷流下载]` 区分提交失败和提交成功后查不到 Hash，记录返回类型、Hash 数量、阶段耗时。
支持新版 `(是否成功, Hash 列表)` 返回值；添加失败不再盲目查询 Hash，已有 Hash 时不再轮询。
下载任务数读取失败时暂停新增，不把连接异常误当成零个任务。
诊断输出不包含密码、Cookie、passkey、完整下载 URL 或原始异常正文；日志仍含主机/IP，请按运维信息管理。
