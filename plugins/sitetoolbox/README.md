# 站点工具箱

插件 ID：`sitetoolbox` · 版本：`1.4.2`

MoviePilot 的站点诊断、监控和维护工作台，整合 RSS、用户数据、缺失文件种子、馒头登录检查，以及原 `siteadapter` 的索引与用户数据解析适配能力。

## 工作台

- **站点诊断**：正常、待观察、连接失败和已确认异常概览；名称/域名搜索、状态筛选、排序、分页、单站复测。
- **右侧详情**：各模块诊断、原因、首次异常、连续天数和最近检测；站点信息展示 RSS 条目与耗时、用户等级、流量及登录记录。
- **维护工具**：缺失种子扫描与确认后清理、RSS 地址修复、用户数据检查、馒头登录检查、适配规则。
- **运行记录**：统一检测各阶段结果、最近后台任务及合并后的系统错误。后台任务完成后页面自动更新，无需反复关闭重开。
- 桌面使用表格与详情侧栏，窄屏使用抽屉，手机显示站点卡片；随 MoviePilot 深浅主题切换。

## 用户数据复测

1.4.2 起，单站复测、用户数据专项检查和统一定时检测都会先通过宿主重新采集用户数据，再检查新记录；只打开页面不会触发采集。此前复测只检查本地快照，可能反复显示早先采集缺失的字段。

本次采集失败时会明确提示失败原因及上次数据时间，不会以旧记录完整为由判为正常。成功后仍使用统一规则清零连续异常天数。

## 统一监控计划

在 **设置 → 监控计划** 中一次配置，RSS、用户数据、缺失种子、馒头登录检查全部共用：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用定时监控 | 开启 | 插件启用时生效。手动检测不受时段限制。 |
| 执行时段 | `08:00–23:00` | 按服务器本地时区；支持 `22:00–06:00` 跨午夜，起止相同表示全天。 |
| 执行方式 | 周期执行 | 可切换为固定时刻，例如 `08:00, 20:00`。固定时刻需在执行时段内。 |
| 执行周期 | 每 2 小时 | 从执行时段起点计算；也可每天一次。 |
| 检测模块 | 全部四项 | 模块仍分别选择站点或下载器，执行时间和确认规则共用。 |
| 异常确认天数 | 3 天 | 所有模块共用一个 1–365 天阈值，设为 1 天即首次异常确认。 |

只注册一个调度入口，按分钟检查当前计划，每个执行时刻去重；正在执行时不会重复启动统一检测。页面下次运行时间由服务器计算。

### 连续异常如何判定

- 按“模块 + 具体站点/下载器/种子”分别记录，共用确认天数。
- 按服务器自然日累计，同一天重复异常只计一天。
- 任一次成功即清零；漏测一天后重新累计。
- 未达阈值为 **待观察**；连接失败会立即展示连接状态，达到阈值后才计为已确认异常并发送定时提醒。
- 用户数据过期天数、网页登录记录最长间隔属于各自的检测条件；确认异常仍使用上面的全局天数。
- 历史独立持久化，重启、修改阈值或只复测部分站点不会清空其他对象的记录。调整阈值立即重新分类最近结果，不增加天数。
- 缺失种子按下载器和 hash 跟踪。下载器查询失败不会当成种子已恢复；下次成功扫描确认缺失项消失时才清零。

例如设为 3 天：前两天只显示观察状态，不触发定时异常提醒或自动清理，第三天继续异常才确认。未检测项目显示未检测，不推断为正常。

### 从旧版本升级

旧 `rss_failure_days` 迁移为全局异常确认天数，已有 RSS 失败历史继续使用。旧版最后一次检测最多补计一个日期，不推测更早记录。

原 RSS、缺失种子和馒头各自的 cron 不再注册，改由统一计划执行；首次升级使用上述默认时段和周期，请在设置中检查。原站点范围、下载器、适配规则、删除文件开关和自动清理开关保留。

## 范围与策略

**设置 → 范围与策略** 可选择监控站点（留空使用所有启用站点）、缺失种子下载器、RSS 请求超时（默认 20 秒）、未配置 RSS 时自动获取（默认开）、自动保存获取到的 RSS（默认关）、用户数据过期天数（默认 2 天）、网页登录记录最长间隔（默认 25 天）。

**设置 → 高级适配** 保留启用插件、用户数据解析规则、适配规则编辑，以及系统错误保留时间（1/3/7 天）。

### 缺失种子清理

扫描只读取 qBittorrent 的 `missingFiles` 任务。手动清理和定时自动清理都只处理已达到连续异常阈值的种子；真正删除前再次按 hash 核对状态，已恢复的任务会跳过。

默认只删除下载器任务、保留数据文件。开启“清理时同时删除数据文件”后，确认弹窗会说明影响。自动清理默认关闭，只有定时监控且自动清理开关开启才会自动执行。

### RSS 修复

重新获取或规范化 RSS，只有解析验证成功才写回站点。站点返回 403/404、Cookie 失效或账号等级没有 RSS 权限时会保留原因。带 Cookie 的请求保留站点 User-Agent。

## API

所有插件接口使用 MoviePilot 鉴权；配置读写继续使用宿主的管理员配置接口。

| 方法与路径（前缀 `/api/v1/plugin/sitetoolbox`） | 用途 |
| --- | --- |
| `GET /overview` | 站点、统一计划、服务器下次运行、维护结果及任务记录 |
| `GET /options` | 配置范围选项 |
| `POST /monitor/run` | 统一检测；可传 `site_ids` 和 `modules` 做复测 |
| `GET /errors?query=&level=all&page=1&limit=20` | 最近有界日志样本的搜索与聚合，隐藏常见凭据 |
| `POST /test/rss`、`/test/rss/{site_id}` | 专项 RSS 检测 |
| `POST /repair/rss`、`/repair/rss/{site_id}` | RSS 修复 |
| `POST /check/userdata` | 用户数据健康检查 |
| `POST /mteam/login/check` | 馒头登录检查 |
| `POST /cleanup/missing/preview` | 缺失种子扫描 |
| `POST /cleanup/missing` | 清理达到阈值的预览项 |

系统错误只读取最近 2 MiB 样本并按来源、级别、消息合并，页面会标明样本范围，避免将几十万行日志全部载入页面。

## 站点适配配置

配置格式兼容原 `站点适配器` 插件。单个站点配置由三部分组成：

```json
{
  "domain": "example.com",
  "indexer": {},
  "userdata": {}
}
```

| 字段 | 说明 |
| --- | --- |
| `domain` | 站点域名。可以写 `example.com`，也可以写完整 URL。插件会归一化成 host。 |
| `indexer` | 资源索引规则。会传给 MoviePilot 的 `SitesHelper().add_indexer(domain, indexer)`。 |
| `userdata` | 用户数据解析规则。用于修正站点管理中的用户数据字段。 |

支持直接粘贴 JSON 对象、JSON 数组、包一层 `sites` / `rules` 的对象，或多行 base64 格式：

```text
域名|配置 JSON 的 base64 编码
```

最小示例：

```json
{
  "domain": "example.com",
  "indexer": {
    "schema": "NexusPhp",
    "search": {},
    "torrents": {}
  },
  "userdata": {
    "calculate_ratio": true,
    "fields": {
      "upload": "//span[@id='uploaded']/text()",
      "download": "//span[@id='downloaded']/text()",
      "bonus": {
        "xpath": "//span[@id='bonus']/text()",
        "regex": "([0-9,.]+)",
        "type": "float"
      }
    }
  }
}
```

`userdata.fields` 支持字符串 XPath、对象规则和候选规则数组。对象规则可用参数包括 `value`、`xpath`、`attribute`、`index`、`regex`、`group`、`ignore_case`、`replace`、`type`、`only_empty`、`continue`。

常用目标字段包括 `username`、`user_level`、`userid`、`upload`、`download`、`ratio`、`bonus`、`seeding`、`leeching`、`active`、`seeding_size`。类型包括 `size`、`int`、`float`、`text`、`active`。

## 状态说明

- `正常`：RSS 可以获取并解析到至少一条资源。
- `待观察`：本次请求失败或没有解析到条目，但连续失败天数尚未达到阈值。
- `警告`：连续失败达到阈值，本次 RSS 可访问但没有解析到条目。
- `异常`：连续失败达到阈值，本次仍未配置 RSS、链接过期、请求失败或解析失败等。
- `连接失败`：站点本身无法正常访问，RSS 结果暂不参与异常判定。

## 注意

- RSS URL 中疑似 `passkey`、`token` 等敏感参数会在页面显示时脱敏。
- 插件不会默认修改站点配置，只有开启 `自动保存获取到的RSS` 才会写回站点 RSS 地址。
- 部分站点需要有效 Cookie 或 User-Agent；插件会复用站点配置中的 Cookie、UA、代理和超时设置。
- 站点适配配置不应写入站点 Cookie、账号、密钥等敏感信息。
- 从 `siteadapter` 迁移时，可以把原插件的 `站点适配配置` 原样复制到工具箱。
- 缺失种子清理当前面向 qBittorrent 的 `missingFiles` 状态；清理前应先查看详情页预览结果。
